# 겨울방학 이스터에그 테마 설계

## 목적

기존 여름방학 그림일기 앱에 숨겨진 겨울방학 테마를 추가한다. 사용자는 사진 선택 화면에서 특정 문구를 연속으로 눌러 테마를 발견할 수 있고, 활성화 후에는 언제든 명시적인 버튼으로 여름 테마로 돌아갈 수 있다.

테마 전환은 화면의 색상, 장식과 계절 문구에만 영향을 준다. 사진 선택, AI 검사, 광고, 사용량, 일기 저장, 달력, 공유와 완성 이미지 생성 로직은 변경하지 않는다.

## 사용자 흐름

### 겨울 테마 활성화

1. 사진 선택 화면의 `어떤 여름이었나요?`에서 `여름` 단어만 누를 수 있는 영역으로 제공한다.
2. 첫 번째 탭은 별도 알림 없이 카운트를 시작한다.
3. 두 번째부터 각각 `겨울방학까지 3번 남았어요`, `겨울방학까지 2번 남았어요`, `겨울방학까지 1번 남았어요` 토스트를 표시한다.
4. 다섯 번째 탭에서 `겨울방학 테마가 열렸어요` 토스트를 표시하고 겨울 테마로 즉시 전환한다.
5. 연속 탭 사이에 2초 이상 간격이 생기면 카운트를 0으로 초기화한다.
6. 다섯 번째 탭 이후의 중복 입력은 추가 동작을 만들지 않는다.

활성화 영역은 일반 텍스트처럼 보이되 키보드와 보조 기술에서도 사용할 수 있는 버튼 의미를 가진다. 아이콘과 이모티콘은 사용하지 않는다.

### 겨울 테마 유지와 해제

- 활성화된 테마는 앱 전용 `localStorage` 키에 `winter` 값으로 저장한다.
- 앱을 닫거나 새로고침한 뒤에도 겨울 테마를 복원한다.
- 겨울 테마가 활성화된 동안 온보딩을 포함한 모든 화면 오른쪽 위에 작은 `여름으로 돌아가기` 텍스트 칩을 표시한다.
- 복귀 버튼을 누르면 즉시 여름 테마를 적용하고 저장된 겨울 설정을 제거한다.
- 저장소에 알 수 없는 값이 있거나 읽기에 실패하면 여름 테마를 기본값으로 사용한다.
- 저장에 실패해도 현재 실행 중의 테마 전환은 유지한다.

## 구조

### 테마 상태

`useSeasonTheme` 훅이 다음 책임만 가진다.

- `summer | winter` 상태 제공
- 초기 저장값 검증과 복원
- 겨울 테마 활성화
- 여름 테마 복귀
- 브라우저 제목 동기화

저장 키는 기존 Origin 마이그레이션 대상에 자연스럽게 포함되도록 `summer-vacation-diary:` 접두사를 사용한다. 테마 상태는 서버나 Supabase에 저장하지 않는다.

### 잠금 해제 인터랙션

`SeasonThemeUnlock`은 탭 횟수, 2초 타이머와 토스트만 담당한다. 테마 저장이나 화면 스타일을 직접 다루지 않고 다섯 번째 입력에서 전달받은 활성화 함수를 호출한다. 컴포넌트가 사라질 때 대기 중인 타이머를 정리한다.

### 복귀 인터랙션

`SeasonThemeReset`은 겨울 테마일 때만 렌더링한다. 텍스트는 `여름으로 돌아가기`로 고정하며 이미지, 아이콘과 이모티콘을 사용하지 않는다. 주요 CTA보다 약한 작은 칩 형태로 표시하되 모바일에서 누를 수 있는 영역과 접근 가능한 이름은 충분히 확보한다.

### 계절 문구

`seasonCopy`는 사용자에게 노출되는 다음 문구만 테마별로 제공한다.

- 브라우저 및 앱 표시 제목
- 사진 선택 화면 제목과 사진 선택 버튼
- 공유 제목과 소개 문구
- 첫 일기 및 7일 기록 축하 문구

내부 저장 키, 딥링크, 일기 ID, 다운로드 파일명, AI 역할과 프롬프트, 분석 결과 및 Mock 데이터는 현재 값을 유지한다.

## 시각 디자인

### 온보딩

- 여름 테마는 현재 온보딩을 그대로 사용한다.
- 겨울 테마는 `winter-theme-export`의 `WinterOnboarding`, 색상 토큰과 에셋을 현재 앱의 버튼 및 safe-area 구조에 맞게 이식한다.
- 제공된 이미지의 비율과 레이어 순서를 유지한다.
- `prefers-reduced-motion: reduce`에서는 겨울 장식과 제목 애니메이션을 정지한다.

### 앱 내부 화면

- 앱 최상위 요소에 `theme-winter` 클래스를 추가한다.
- 겨울 토큰으로 하늘, 눈 덮인 종이 배경, 원고지 선, 기본 및 보조 버튼, 진행 표시, 알림 카드와 달력의 색감을 전환한다.
- 내부 장식은 제공된 눈송이와 구름 이미지를 제한적으로 사용하며 제목, 광고와 버튼의 터치 영역을 침범하지 않는다.
- 기존 날씨와 낮·밤 클래스는 그대로 유지한다. 선택값, 상태 전이와 저장 데이터는 바뀌지 않는다.
- 날씨 효과와 겨울 배경이 함께 표시될 때 텍스트 대비와 버튼 가독성을 우선한다.
- 완성 미리보기와 저장된 JPEG 디자인에는 겨울 테마를 적용하지 않는다.

### 복귀 버튼 배치

- 온보딩과 앱 내부 화면 모두 safe area를 고려한 오른쪽 위에 배치한다.
- 겨울 장식과 겹치더라도 텍스트가 읽히도록 반투명 종이색 배경과 얇은 테두리를 사용한다.
- 네이티브 내비게이션, 앱 제목, 광고 영역과 겹치지 않도록 각 화면 컨테이너 안에서 위치를 조정한다.
- 작은 화면에서도 문서 스크롤이나 레이아웃 높이를 추가하지 않는 오버레이 요소로 구현한다.

## 데이터와 기능 불변 조건

테마 전환 전후에 다음 값과 흐름은 동일해야 한다.

- 사용자 식별 키와 Supabase 요청
- AI 검사 기회 소비, 충전과 광고 보상
- 사진 크롭 및 그림 변환 입력
- 일기 작성 단계와 초안 상태
- 날짜별 최대 저장 개수와 기존 일기 데이터
- 일기 달력 탐색, 스와이프, 삭제 및 공유
- 완성 이미지의 픽셀 구성과 다운로드 파일명
- Apps in Toss 앱 이름, 딥링크와 광고 ID

테마 전환은 진행 중인 초안이나 열려 있는 화면을 초기화하지 않는다.

## 오류 처리

- `localStorage` 읽기 오류: 여름 테마로 시작한다.
- 유효하지 않은 저장값: 무시하고 여름 테마로 시작한다.
- `localStorage` 쓰기 또는 삭제 오류: 화면의 현재 테마는 전환하되 다음 실행 유지 여부만 포기한다.
- 겨울 에셋 로드 실패: 배경색과 CSS 토큰만으로 화면과 기능을 사용할 수 있어야 한다.
- 연속 탭 도중 화면 이동: 타이머와 카운트를 초기화한다.

## 접근성

- `여름` 활성화 영역은 버튼으로 인식되지만 주변 제목과 자연스럽게 함께 읽힌다.
- 복귀 버튼은 `여름으로 돌아가기`라는 명시적인 텍스트와 접근 가능한 이름을 가진다.
- 키보드 Enter와 Space 입력도 탭과 동일하게 처리한다.
- 토스트 없이도 최종 테마 전환과 복귀 상태를 화면 문구로 확인할 수 있다.
- 색상만으로 테마 복귀 기능을 표현하지 않는다.
- 아이콘과 이모티콘을 사용하지 않는다.

## 검증

### 인터랙션

- 네 번 입력으로는 겨울 테마가 열리지 않는다.
- 다섯 번째 입력에서 한 번만 활성화된다.
- 입력 사이에 2초가 지나면 다시 다섯 번이 필요하다.
- 토스트의 남은 횟수가 실제 카운트와 일치한다.
- 활성화 후 새로고침과 앱 재실행에서도 겨울 테마가 유지된다.
- 모든 화면에서 복귀 버튼이 보이고 여름 테마로 돌아간다.
- 복귀 후 다음 실행도 여름 테마로 시작한다.

### 회귀

- 테마 전환 전후 동일한 사진과 일기로 동일한 완성 이미지를 만든다.
- AI 검사 기회, 광고 보상과 서버 요청 횟수가 테마 전환의 영향을 받지 않는다.
- 기존 저장 일기와 진행 기록이 그대로 보인다.
- 달력 상세, 공유 모달과 종료 확인 모달의 레이어 순서가 유지된다.
- 작은 모바일 화면에서 복귀 버튼과 겨울 장식이 광고, 제목과 CTA를 가리지 않는다.
- 낮·밤 및 모든 날씨 조합에서 읽기 대비를 확인한다.
- 모션 감소 설정에서 겨울 애니메이션이 정지한다.

### 자동 검사와 빌드

- `npm run lint`
- `./node_modules/.bin/tsc --noEmit -p tsconfig.app.json`
- `npm run build`
- `npm run build:test`

- 겨울용 AI 프롬프트와 분석 결과 변경
- 겨울용 완성 이미지 템플릿
- 겨울용 저장소, 백엔드 또는 Supabase 분기
- 계절별 광고 설정
- 사용자에게 공개되는 일반 테마 설정 화면
- 여름과 겨울 외의 추가 테마
